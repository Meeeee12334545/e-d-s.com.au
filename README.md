# EDS website

The marketing site for Environmental Data Services. The pages are static (no
framework), so `dist/` can be uploaded to any web host. A small optional Node
server in `server/` serves the same pages and adds a private visit-analytics
dashboard at `/admin`.

```bash
npm install
npm run dev      # builds, then runs the server on http://localhost:4173
npm run build    # writes dist/
npm start        # runs the server on an existing dist/
```

`STATIC_HOST=1 npm run build` leaves out the visit tracker, for hosts with no server (GitHub Pages). `PREVIEW=1 npm run build` does the same and adds a no-index tag and a `Disallow: /` robots.txt, for copies that are not the live site. `SITE_URL=https://... npm run build` changes the address used for canonical links, share cards and the sitemap (default: `site.url` in `content.mjs`).

Every push to `main` publishes the site to GitHub Pages at www.e-d-s.com.au (`.github/workflows/publish.yml` builds with `STATIC_HOST=1`, adds a `CNAME` file for the domain and pushes `dist/` to the `gh-pages` branch). The domain's DNS is at Digital Pacific: `www` is a CNAME to `meeeee12334545.github.io`, and the bare domain has GitHub's four A records.

Old Squarespace addresses (`/hach-flow`, `/what-we-do` and so on) forward to their new pages through small pages the build writes from `oldPages` in `content.mjs`. GitHub Pages cannot send a real redirect, but Google takes their instant refresh as a permanent one, so they carry no noindex and the old addresses' standing in search passes to the new pages. Documents the old site served from `/s/<file name>` still work: the build copies each document listed in `oldFiles` to its old address.

The build stops with an error if a page repeats an element id, since product links, "On this page" lists and form labels all depend on ids being unique. It warns when a page's title runs past 60 characters or its description past 160 (about what Google shows), or when two pages share either.

## Search

Each page's title and description are what Google shows for it. A service, solution or brand page is titled "<title> | EDS" unless it has a `pageTitle` in `content.mjs`, which adds the words people search for ("Sampler Hire", "in Australia") that the short name leaves out; keep those to words the page's copy already uses. Its description is its `summary` unless it has a `description`, for a summary too short to fill the line under the title (about 120 to 155 characters). The sitemap gives every page the date its content last changed (its title, description, structured data and `<main>`, not the menus or footer): the publish workflow hands the build the dates from the last publish (`assets/page-dates.json` on the `gh-pages` branch, through `PAGE_DATES`), and a page that has not changed keeps its date. A build without them, such as a local one, dates every page today.

- **Structured data** (`jsonLd()` in `build.mjs`). The home, About and Contact pages describe EDS as an organisation (its four offices, its services, the logo and contact points, and its profiles elsewhere from `site.profiles`, which Google uses to tie them to the site). The home page also names the website, which is the site name Google shows above each result, and the Contact page gives the head office as a local business with its opening hours. Every service and solution page describes its service as provided by EDS Australia wide, every page with a breadcrumb gives its trail, and pages with questions and answers give them as an FAQ.
- **Share cards.** When a page is shared on LinkedIn, Teams, Facebook or in a message, the card shows the page's first photograph or FlowSense screen, where its shape survives the wide crop those apps make (between 1.2 and 2 times as wide as tall), and otherwise `og-card.jpg`, which the home page always uses (`shareImage()`). The image also goes into the page's structured data.
- **Ownership.** `site.verify` takes the HTML tag tokens Google Search Console and Bing Webmaster Tools offer, for the home page; a domain verified by DNS needs neither.
- **Faster crawling.** After each publish the workflow tells IndexNow (Bing, and through it Copilot and DuckDuckGo, plus Yandex, Naver, Seznam and Yep) which pages changed, using the key in `site.indexNowKey`, which the build publishes as `/<key>.txt` (`tools/indexnow.mjs`; `DRY_RUN=1` lists the pages without sending). Google has no such ping; it reads the sitemap's dates.
- **AI assistants.** The build writes `llms.txt`, a plain list of every page with its description, which some answer engines read in place of the pages.

The rest is outside the code, and it does more for EDS's place in search than anything on the pages:

1. **Google Search Console** (https://search.google.com/search-console): add the domain `e-d-s.com.au` as a domain property (a TXT record at Digital Pacific) and submit `https://www.e-d-s.com.au/sitemap.xml`. Then use URL inspection on the home page and the main service pages and request indexing. Check Pages and Enhancements each month.
2. **Bing Webmaster Tools** (https://www.bing.com/webmasters): import the site from Search Console and submit the same sitemap. Bing's index also serves Copilot and DuckDuckGo.
3. **Google Business Profile** (https://business.google.com) for the head office at Meadowbrook, and for each other office that has staff at a street address (or as a service area business for NSW and ACT, Victoria and South Australia). Use the same name, address and phone as the site, the category "Environmental consultant" or the nearest fit, the services list, opening hours and photographs from the site. Ask clients for reviews after each job, and put the profile's share link in `site.profiles`.
4. **Apple Business Connect** (https://businessconnect.apple.com) and **Bing Places** (https://www.bingplaces.com, which can import from the Google profile), so the offices show in Apple Maps, Siri and Bing Maps.
5. **LinkedIn company page.** Post each project result, white paper and product release with a link to its page, and put the page in `site.profiles`. The share cards show each page's own photograph.
6. **Links from the makers EDS represents.** Ask Detectronic, Hach, ORI, Beadedstream, MicroLevel, Aquamonitrix and Dynaflox to list EDS as their Australian distributor on their "where to buy" pages, with a link to the matching page here (`products/<brand>.html`). These are the strongest links EDS can get.
7. **Industry bodies and directories.** Membership listings with a link: the Australian Water Association (AWA), the Water Industry Operators Association (WIOA, which publishes WaterWorks), state water directories, and the supplier listings EDS already appears in (Environmental Expert, Energy XPRT), each pointing at this site rather than the old addresses.
8. **Papers and talks.** Each conference paper, Ozwater talk or trade press article (Utility Magazine, Inside Water, WaterWorks) about EDS work should link to the matching service page. New white papers go on Resources first.
9. **"Enforce HTTPS"** stays ticked in the repository's Pages settings.

## Analytics dashboard

Sign in at `/admin` to see visitors, visits, page views, bounce rate and time on
page for any period against the period before, plus top pages, entry pages,
sources and campaigns (`utm_*` tags), locations (Australian states from the time
zone), devices, document downloads, email and phone clicks, form submissions,
links to other sites and pages not found. "What people clicked" lists every link,
button, menu, tab and question clicked, named by the words on it, what it belonged
to (a product, say) and where on the page it was (the header, the footer, a section
by its heading), plus searches and the options picked in forms. "Visitor activity"
shows each visit in the period with every step in order, labelled in plain words
("Clicked the button “Add to quote” for Hach FL900"). Nothing typed into a form is
recorded. Everything exports to CSV, with an `action` column in plain words. A
button or link can name itself for the dashboard with `data-track-label`, and a
card can name what its buttons belong to with `data-track-item`.

- **Turn it on** by setting `ADMIN_PASSWORD`. Locally, copy `.env.example` to `.env`
  (git ignores it). Without a password `/admin` explains how to set one.
- **Privacy.** No cookies, and no IP addresses are stored. A visitor is a hash of IP
  and browser with a salt that is replaced daily, so people cannot be followed from
  one day to the next.
- **Organisations and cities.** After each page view the server looks up who holds the
  visitor's network in the internet registries (RDAP, cached per network range) and the
  nearest city in DB-IP's free City Lite database, which it downloads monthly into
  `DATA_DIR`. Then the IP is dropped (`server/lookup.mjs`). `ANALYTICS_LOOKUP=off` turns this off. Bots are filtered out. On the dashboard, tick "Don't count my
  own visits" to leave your browser out.
- **Hosting.** The dashboard needs the server, which runs on any host with Node 22.13
  or later and a persistent disk for `data/` (a VPS, Render, Railway, Fly.io). Run
  `npm ci && npm run build && npm start` behind HTTPS. To keep the pages on a static
  host instead, run the server somewhere else and build the pages with
  `ANALYTICS_ENDPOINT=https://<that server>/api/collect`.
- **Live setup.** The pages are on GitHub Pages at www.e-d-s.com.au. The server runs on
  Render from `render.yaml` at analytics.e-d-s.com.au, so the dashboard is at
  https://analytics.e-d-s.com.au/admin. `PAGES_URL` sends any page request there back to www.
  Every route to a Render service, the custom domain and the `*.onrender.com` address alike,
  passes through Cloudflare, which overwrites `CF-Connecting-IP` with the caller's address. So
  `CLIENT_IP_HEADER=cf-connecting-ip` gives the server each visitor's own address (for the
  per-address limits and the organisation and city lookup). Set it only where nothing can reach
  the server around Cloudflare; on any other host a caller could choose their own address.
- GitHub Pages preview copies leave the tracker out, since nothing there can receive visits.

Other settings (`PORT`, `DATA_DIR`, `ANALYTICS_TZ`, `SESSION_SECRET`, `TRUSTED_PROXIES`, `CLIENT_IP_HEADER`, `PAGES_URL`) are described in `.env.example`.

## Links that carry context

- **Enquiries.** `enquire.html?topic=...&product=...&mode=...` opens the form with the topic chosen (matched against a tile's subject, or a service or solution title), the product named and the way of working ticked (`buy`, `hire`, `managed` or `unsure`). The same works on `contact.html`, where the Sales and Service cards use it to choose their topic without reloading the page. Use `contactHref()` in `build.mjs` rather than writing these by hand. The old site's `/enquire` address is now the enquiry page itself.
- **Products.** Every product card has an id, so `products/hach-flow.html#fl900-portable` opens that product's quick view. On the products page the id is prefixed with the brand: `#hach-flow-fl900-portable`.
- **Instrument finder.** `products/index.html?q=flow#finder` opens the finder already filtered.

## Design rules (shared with EDS FlowSense)

- **Brand.** Daylight first (light refresh, 31 October 2026). The EDS logo teal `#3d9991` (`--eds`, the colour of the official logo in `EDS Main Logos`) is the line that measures: icons, rules, chart lines and focus rings; at 3.4:1 on white it is never body text. The FlowSense teals `#0d7c72` / `#095f57` / `#0c5f59` carry text, links and buttons, and the brand gradient fills the closing call to action and the FlowSense band. Light bands alternate white and shallows (`--bg-alt`, a pale tint of the logo teal); the header, menus, drawer, search, heroes and footer are light, and the header carries the colour logo (`eds-logo-colour.png`, cut from the official PNG). The one showpiece on a page sits on a deep sea teal (`--deep`), not a near-black. `.btn-primary` is the FlowSense teal on light and aqua on a coloured band; `.btn-ghost` is an ink outline on light and a white one on colour.
- **Type.** Headings are Saira (Omnibus-Type, OFL) cut to its semi-expanded width by `tools/fonts.py`, the open-licence face closest to Eurostile, the type of instrument panels and engineering catalogues. Reading text is Helvetica Neue Light: the visitor's own on Apple devices, through `local()` in the "EDS Text" font faces, and elsewhere Aileron (CC0), drawn after Helvetica, whose Regular matches Neue's Light. Semibold asks land on Neue's Medium (in Safari, `local()` resolves by family, so 600 shows Neue's Bold). Geist Mono stays for readouts. Eurostile and Helvetica Neue themselves need a web licence from Monotype to be served; with one, only the `src` of those font faces changes.
- **Icons.** Lucide only (https://github.com/lucide-icons/lucide, ISC), inlined at build time by `icon()` in `build.mjs`. Stroke 2, round caps. If Lucide lacks a glyph, draw one in the same style; do not mix in Phosphor or Heroicons.
- **Scroll reveals** are a short rise (14 px over .6 s, `[data-reveal]`), not a slide, so a page settles rather than performs; the one orchestrated moment is the home headline's words rising on load. Hero blocks rise at first paint by a CSS keyframe rather than waiting for `site.js`.
- **Icon motion.** Ideas after animate-ui (https://github.com/imskyleen/animate-ui), written from scratch in CSS because its licence does not allow copying. Gestures last about a second and carry their own rest. Use the individual `rotate` / `translate` / `scale` properties, never `transform`.
- **Surface effects.** The card edge spotlight, the beam round the hero meter card and the drawn link underline follow VengeanceUI components (https://github.com/Ashutoshx7/VengeanceUI, MIT), rewritten in plain CSS. The film grain on dark bands, teal-tinted shadows, the home services bento and the sparing use of eyebrow labels follow taste-skill (https://github.com/Leonxlnx/taste-skill, MIT).
- **Motion is full for everyone.** By EDS's decision (2 October 2026) the site always animates and has no reduced-motion mode or switch; it does not follow a device's Reduce Motion setting.
- **One card family.** Every card-like block (cards, features, results, steps, ways, range tiles) shares the 16 px radius and 28 px padding. A border and the lift on hover mean "this opens something": only a card that is a link has them, and it carries a plain arrow in its corner (`.go`, no ring; it slides on hover) instead of a "Learn more" label; the title is the link text. A card carries its icon plain, drawn large in the brand (layout and feel pass, 31 October 2026); the tinted chip (`.card-icon`) is kept for a row in a list, where the icon is the row's bullet (the hero facts, the FlowSense items, documents, offices), and for a tile that fills when it is picked (the enquiry topics). A panel of facts that is not a link (a feature, a result, a step, a sidebar card) is a tone on its band instead, pale grey on white bands and white on pale grey ones, with no border and no lift; short lists that need no panel at all (offices, related links, how a program runs, product highlights) are ruled rows (polish pass, 24 October 2026). Optional `tags` on a service or solution (short facts already in the copy) show as chips on its card.
- **Type scale.** Three heading steps: a page title (`.h-lg` in a hero, and the closing call to action), a section head on the home and index pages (`.section-head > .h-lg`), and a band head inside a page (`.band-head > .h-lg`, the same for every band on service, solution, product and FlowSense pages). Card, column and panel titles (h3, h4) take reading leading. Ledes are measured in em (34em, about 75 characters) and balanced. Copy is set with typographer's apostrophes, and a number never parts from its unit at a line end: `layout()` in `build.mjs` does both on every page, so `content.mjs` keeps plain ticks and spaces. `layout()` also keeps time units (weeks, days, hours and so on), a standard's name with its number (AS/NZS, ISO) and the groups of the 1300 number together, and card, column and list titles balance like the headings.
- **Menus explain themselves.** Each item in the Services, Solutions and Products menus shows its summary (or tag, or lede) under its name, clamped to two lines, and the Services panel ends with a line for visitors who are unsure. The Products menu has two labelled columns, Ranges and Instruments (the product pages, each with its `tag`). On screens 780 px tall or less the summaries clamp to one line, so the Services panel fits without scrolling.
- **Page layout.** From the October 2026 layout review, after taste-skill, Anthropic's frontend-design and the FlowSense design-review skill:
  - The home page tells one story in ten bands: hero, client logos with the proof row (`proof` in `content.mjs`: four statements at one weight, each a claim made elsewhere on the site), services, results, the city, buy, hire or DaaS, FlowSense, the instrument shelf (`shelf`: four flagship instruments shown large on one white plate, then the eight ranges as links), the EDS story with offices and industries, and the call to action. The city is its one interactive showpiece; the flow lab lives on the sewer flow and I&I pages, the office map on About and Contact, the white papers on Resources.
  - A hero holds four text groups at most (label, headline, a paragraph of 20 words or fewer, buttons) and is sized to its content, so what follows is in the first screen. The home hero holds three: no label, and its headline in one colour. Inner page heroes start close under the header (`.page-hero` padding), so the breadcrumb, title and buttons sit in the first screen beside the product shot or jump list. The client logos sit directly under the home hero as a still grid, every mark in one grey at one optical height (colour on hover), with the key figures beneath. Inner-page hero copy starts at the top of its row beside the visual, so the breadcrumb and title sit at the same height from page to page. Brand and product heroes keep their product plate on tablets (smaller, uncaptioned) and phones (a short plate under the buttons) through the `has-product` class `pageHero` adds, and brand pages have no contact card in the aside.
  - Coloured bands run on a schedule: one showpiece or demo in the deep sea teal, and the closing call to action in the brand teal. Everything else is light, the heroes included; light bands alternate white and shallows.
  - The E-Flow 3 page draws its illustrations as instrument screens: the drawing kit's dark variant on a deep teal plate with a faint grid and frame marks (`dg-screen` in `diagrams.mjs`), inside light bands, so they read as one family with its changeover demo (3 November 2026). Its hero plate and sensor anatomy use the same screen, and the hero loops one storm: water, beams and status are separate layers moved by transform and opacity alone (`eflowHero()` in `build.mjs`). Glows on these drawings are wide faint strokes, not SVG filters, which would repaint on every frame of the moving parts beside them.
  - Service and solution pages give each section a full-width band in a layout that suits it, so no two neighbours look alike (`bandsOf()` in `build.mjs`): the first feature list as cards, later ones as a row of deliverables across the page, checklists in two columns (read down each column), tables across the page (one row per aspect on a phone), questions beside their heading, numbered steps in a row, and a block's `products` as instruments on a plate, each a link to its page. Results from the field follow the first feature band, so the evidence comes before the reference material. Every band heading is set at the same size, one step below the page title. A service with two results shows them with a third tile listing the other results. A slim section bar replaces the old numbered contents list (a hairline under the current section's link fills as the section scrolls by), and the related links share one band near the end. The opening text runs across the page, beside its photo or product shot, or with the first paragraph beside the rest (`overviewHtml()`). It has no contact card: the hero, the section bar and the closing band carry the enquiry links. A block can carry `nav`, its short label in the section bar (`nav: ""` leaves it out). A feature list of two, a feature list straight after a row of deliverables, or a checklist straight after another sits beside its heading as ruled rows (a split band). A service can list `downloads`, shown as a group in the Related band, which always has four columns (two on a tablet). Result cards are a four-row subgrid, so their lines align across a row, and `results[].services` may name solution pages too.
  - A label above a heading (`.eyebrow`) is set like the services index kicker: the display face in sentence case, in the brand, with a short rule before it (31 October 2026; the tracked uppercase labels and the middle-dot lists are gone). At most one for every three sections, and a label that repeats the breadcrumb is left out. Capitals stay for group headings on panels, menus, tables and footer, and for instrument readouts, where small uppercase is a convention rather than a flourish.
  - One label per action, everywhere: "Start an enquiry" opens the enquiry form, "Request pricing" asks for a price, "Contact us" goes to the contact page.
  - The footer carries a credentials row on every page: the Ex and IECEx marks, Australian owned since 1991, Sydney Water panel provider.
  - Each page has one deep showpiece between its hero and its close at most: on About the office map closes the page and carries the enquiry, rather than a separate call to action.
  - The client logos are each set at a height worked out from their own proportions (`logoGrid()` in `build.mjs`), so a roundel and a wide wordmark carry the same weight. On the city, the toolbar, caption, readings, key and note stack under the stage, and a district's sensor pills are lifted clear of each other and of its name label in the page view as well as the expanded one. The toolbar toggles mark their state with `data-pressed`, since their visible labels already change.
- **Simulations are labelled.** The flow lab, LIDoTT demo, E-Flow 3 changeover demo, Asset Score dial, FlowSense screens and the drawings in `diagrams.mjs` are illustrations and say so on the page. Do not present them as live data, and do not use client site names in them. The FlowSense screen drawings mark their finest labels `fine`, hidden below 600 px as the city's are. The Pump Station Manager pins on `flowsense.html` sit in each panel's own white space and scale with the screen, so check them at 1440, 1100 and 990 after a brochure change.
- **Photographs are EDS's own, or were on the old site.** Captions describe what is in the picture and claim nothing the copy does not already say; no client or site names. Blue Siren material is not used: EDS no longer sells that range.
